Software engineering is not a single discipline but a cluster of overlapping concerns: how code is written and structured, how systems are deployed and maintained, how teams form and communicate, and how professional skill develops or erodes over time. The sources gathered here cover that full range, and their tensions are at least as instructive as their individual claims.

On the craft of code, several pieces argue for restraint and legibility over cleverness. ["Deep modules"](/reading/2026-05/2026-05-04t231343-ai-likes-deep-modules) — small interfaces hiding large implementations — reduce cognitive overhead for both humans and LLMs. [The Single Responsibility Principle](/reading/2026-06/2026-06-04t073318-single-responsibility-the-distorted-principle) is widely misread as "do one thing" when it actually means grouping behaviors under a single coherent responsibility; over-granularizing classes can produce more complexity, not less. [Reflexive destructuring in JavaScript](/reading/2026-07/2026-07-16t052353-boundary-aware-styling-in-css) is a similar case: optimizing for writing speed over reading clarity. [Anton Zaides's unwritten laws](/reading/2026-06/2026-06-10t073045-the-unwritten-laws-of-software-engineering) — roll back before debugging, treat every dependency as a future outage — represent the kind of hard-won operational knowledge that doesn't appear in onboarding docs.

The question of what engineers actually need to know sits at the center of several debates. [Algorithm interviews](/reading/2026-04/2026-04-30t155134-learn-algorithms-for-interviews-forget-them-for-work) test a narrow trainable skill that weakly predicts production performance; real work requires reading tradeoffs and shipping incrementally against messy, unbounded inputs. [Tacit knowledge](/reading/2026-05/2026-05-19t110710-the-tacit-dimension-why-your-best-engineers-cant-tell-you) — pattern recognition, unwritten conventions, design intuition — is structurally inaccessible to AI tools and transmits only through apprenticeship. [Senior developers fail to communicate their expertise](/reading/2026-05/2026-05-13t060018-why-senior-developers-fail-to-communicate-their-expertise) in part because they frame work as complexity management while the rest of the business thinks in terms of uncertainty reduction.

AI's effect on engineering craft is where the most active disagreement lives. [Lars Faye](/reading/2026-04/2026-04-27t145041-agentic-coding-is-a-trap) argues that full agentic workflows accelerate skill atrophy and invert developer priorities toward speed over understanding. [The Lobster in the Hot Pot](/reading/2026-05/2026-05-03t103944-the-lobster-in-the-hot-pot) makes a related point about institutional knowledge eroding slowly enough that nobody notices until the cost shock arrives. [Val Town's "Slow Mode"](/reading/2026-05/2026-05-19t193626-slow-mode) proposal — a human-in-the-loop agent that teaches rather than replaces — tries to split the difference, trading short-term velocity for genuine skill retention. Against these, [The Typical Set](/reading/2026-05/2026-05-06t110728-the-bottleneck-was-never-the-code) argues the real bottleneck was never code generation but organizational alignment; cheap code amplifies whatever coherence or dysfunction already exists. [Werner Vogels](/reading/2026-06/2026-06-30t173037-a-return-to-two-pizza-culture) sees compressed prototyping time as reason to restructure the build-measure-learn loop itself.

Code quality under AI generation is a distinct but related concern. [Yusuf Aytas](/reading/2026-05/2026-05-22t091746-when-code-is-cheap-does-quality-still-matter) notes that AI lowers the cost of producing code but not the cost of owning it; LLMs can generate polished technical debt faster than any individual engineer. [Abednego Gomes](/reading/2026-05/2026-05-14t223612-the-perils-of-ai-to-the-software-engineering-profession) argues "vibe coding" — shipping AI-generated code without review — is categorically incompatible with safety-critical systems. [Imbue's experiment](/reading/2026-06/2026-06-23t212958-how-ai-code-review-can-make-correct-code-worse) found that weaker AI fixer agents break correct code when they overreach beyond review scope. [Armin Ronacher](/reading/2026-06/2026-06-23t161552-the-coming-loop) warns that outer harness loops amplify LLMs' worst tendencies — defensive, opaque code — and risk producing codebases that require machine participation to maintain.

Testing and verification span multiple layers. [Playwright tests break during UI refactors](/reading/2026-05/2026-05-05t135218-designing-playwright-tests-that-survive-ui-refactors) not because of selector choices alone but because they couple to implementation details rather than semantic roles. [AI-generated frontend tests](/reading/2026-06/2026-06-22t185420-code-smells-when-you-get-ai-to-write-your-frontend-tests) introduce recurring code smells — over-mocking, happy-path bias, tests that match buggy implementations rather than intended behavior. [Daniel Stenberg's curl data](/reading/2026-05/2026-05-02t094735-approaching-zero-bugs) suggests that despite AI-assisted static analysis, there is no measurable sign yet that open-source projects are approaching zero latent bugs. [Jane Street's Yaron Minsky](/reading/2026-06/2026-06-15t021106-formal-methods-and-the-future-of-programming) argues formal methods are newly cost-effective precisely because agents lower the cost of writing proofs while also creating urgent demand for verification beyond what tests alone can provide.

Infrastructure and tooling decisions carry their own craft considerations. [Container filesystems](/reading/2026-05/2026-05-04t231858-how-container-filesystem-works-building-a-docker-like) built from Linux primitives, [SSH key management](/reading/2026-05/2026-05-04t231548-using-ssh-keys-to-make-connectivity-simpler-and-secure), [shell scripting safeguards](/reading/2026-04/2026-04-30t231815-shell-tricks-that-actually-make-life-easier-and-save-your), and [distributed trace reading](/reading/2026-06/2026-06-10t220929-navigating-the-age-old-problem-of-checkmarks-in-ui-with) all represent operational knowledge that accumulates through use rather than specification. [Jujutsu's approach to version control](/reading/2026-05/2026-05-31t164554-jj-vcsjj) — auto-committing the working copy and treating conflicts as first-class objects — surfaces assumptions that Git leaves implicit.

Organizational dynamics shape engineering outcomes as much as individual skill. [Poor onboarding](/reading/2026-05/2026-05-08t112608-your-onboarding-is-a-hazing-ritual-and-you-call-it-agile) disguised as agile process sets new hires up to fail while making the dysfunction invisible to management. [Tech hiring's decay](/reading/2026-06/2026-06-22t182141-the-systemic-decay-of-tech-hiring) follows from error asymmetry, diffuse accountability, and Goodhart's Law applied to interview processes. The split between engineers who prioritize shipping and those who insist on quality [may be less about values than about organizational context](/reading/2026-07/2026-07-07t170607-the-software-engineering-war).
