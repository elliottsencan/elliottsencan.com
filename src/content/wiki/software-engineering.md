Software engineering is not a single discipline but a layered set of practices: writing and reviewing code, designing systems, managing dependencies, testing behavior, and sustaining organizational knowledge over time. The sources here span all those layers, and the thread running through most of them is a single pressure: AI tools are lowering the immediate cost of producing code without lowering the cost of owning it.

The ownership gap shows up in several forms. [Yusuf Aytas](/reading/2026-05/2026-05-22t091746-when-code-is-cheap-does-quality-still-matter) puts it directly: taste, judgment, and bounded prompting still matter because LLMs can generate polished, well-formatted technical debt faster than any individual engineer ever could. [Lars Faye](/reading/2026-04/2026-04-27t145041-agentic-coding-is-a-trap) frames full agentic workflows as accelerating skill atrophy and inverting developer priorities toward speed over understanding. [Val Town's Pete Millspaugh](/reading/2026-05/2026-05-19t193626-slow-mode) proposes a "Slow Mode" agent that keeps humans involved at every step — planning together, teaching concepts, never autonomously looping — trading short-term productivity for genuine learning. [Abednego Gomes](/reading/2026-05/2026-05-14t223612-the-perils-of-ai-to-the-software-engineering-profession) calls shipping AI-generated code without review "vibe coding" and argues it is categorically incompatible with safety-critical systems. [Anton Zaides at Manager.dev](/reading/2026-08/2026-08-31t131721-the-i-dont-know-claude-wrote-this-pandemic) names the social form of the same problem: engineers who cannot explain code they submitted have surrendered cognitive ownership.

Code quality questions extend to architecture. [Go Monk](/reading/2026-05/2026-05-04t231343-ai-likes-deep-modules) argues that deep modules — small interfaces hiding large implementations — reduce complexity for humans and LLMs alike. [Henrique F. Teixeira](/reading/2026-06/2026-06-04t073318-single-responsibility-the-distorted-principle) argues that Single Responsibility is widely misapplied: it means cohesive grouping under a single accountable responsibility, not atomizing classes into meaningless fragments. [Kobi Hari](/reading/2026-04/2026-04-30t232001-a-better-way-to-build-angular-components-from-inputs-to) applies the same logic to Angular component design, arguing that input-bloated components should be decomposed into directives and sub-components rather than god-object monoliths.

Testing surfaces its own set of recurring failures. [The Currents team](/reading/2026-05/2026-05-05t135218-designing-playwright-tests-that-survive-ui-refactors) argues that Playwright suites break on refactors not because of selector choice alone but because tests couple to DOM structure and CSS classes rather than semantic roles and accessible names. [How To Test Frontend](/reading/2026-06/2026-06-22t185420-code-smells-when-you-get-ai-to-write-your-frontend-tests) documents over twenty recurring AI-generated test smells, including over-mocking, only exercising happy paths, and writing assertions that confirm a buggy implementation rather than intended behavior. [Imbue researchers](/reading/2026-06/2026-06-23t212958-how-ai-code-review-can-make-correct-code-worse) found that weaker AI fixer agents in a review pipeline overreach beyond review scope, breaking correct code — softer instructions eliminated catastrophic regressions.

CI infrastructure at scale has its own texture. [Sam Alba at Mendral](/reading/2026-04/2026-04-30t195531-what-ci-actually-looks-like-at-a-100-person-team) describes an AI agent handling CI triage for PostHog across 575K weekly jobs and 33M test executions, ingesting billions of log lines to trace flaky tests to root causes and open fix PRs automatically.

Security crosses all these layers. [Dan Goodin at Ars Technica](/reading/2026-04/2026-04-30t231634-supply-chain-attack-using-invisible-code-hits-github-and) reports attackers encoding payloads in invisible Unicode variation-selector characters across 151 malicious npm and GitHub packages — undetectable by code reviewers and static analysis, yet executable at runtime. [Emphere Engineering](/reading/2026-06/2026-06-11t024225-testing-a-security-tool-like-it-can-hurt-people) describes building deterministic assurance for a container security tool using fixture invariants and red runs that prove the system fails loudly when it overclaims certainty.

Organizational process shapes what engineering can accomplish regardless of individual skill. [The Typical Set](/reading/2026-05/2026-05-06t110728-the-bottleneck-was-never-the-code) argues the real bottleneck was always shared context, specification clarity, and management coherence — coding agents amplify whatever alignment or misalignment already exists. [DHg](/reading/2026-05/2026-05-08t112608-your-onboarding-is-a-hazing-ritual-and-you-call-it-agile) shows how poor onboarding disguised as agile process — packed calendars, same-sprint workloads from day one — sets new hires up to fail while making the dysfunction invisible to management.

Expertise transmission is a persistent problem. [cekrem](/reading/2026-05/2026-05-19t110710-the-tacit-dimension-why-your-best-engineers-cant-tell-you) draws on Polanyi's philosophy of tacit knowledge to argue that the most valuable engineering judgment — pattern recognition, design intuition, unwritten conventions — is structurally inaccessible to AI tools and can only be transmitted through apprenticeship. [Tuhin Nair](/reading/2026-05/2026-05-13t060018-why-senior-developers-fail-to-communicate-their-expertise) locates a related gap between senior developers who think in terms of complexity management and business stakeholders who think in terms of uncertainty reduction.

[Fagner Brack](/reading/2026-04/2026-04-30t155134-learn-algorithms-for-interviews-forget-them-for-work) offers a useful corrective to how the profession recruits: algorithm interviews test a narrow, trainable skill that weakly correlates with production performance. Real engineering requires reading tradeoffs, shipping incrementally, and handling messy unbounded real-world inputs.

[Anton Zaides](/reading/2026-06/2026-06-10t073045-the-unwritten-laws-of-software-engineering) distills production-incident wisdom into seven rules — including rolling back before debugging and treating every external dependency as a future outage — that no benchmark or interview question surfaces. [Paolo Galeone](/reading/2026-08/2026-08-05t072544-use-your-brain-engineering-standards-in-the-age-of-llms) adds that strong CI/CD and code ownership are what let teams use AI as an amplifier rather than a replacement for judgment.

The debate is not resolved by any single source. Some — [Werner Vogels](/reading/2026-06/2026-06-30t173037-a-return-to-two-pizza-culture) and [Anthropic's Justin Young](/reading/2026-05/2026-05-19t221035-effective-harnesses-for-long-running-agents) — are optimistic that agent workflows compress real prototyping cycles. Others — [Armin Ronacher](/reading/2026-06/2026-06-23t161552-the-coming-loop) and [Dex Horthy](/reading/2026-07/2026-07-23t215330-humanlayeradvanced-context-engineering-for-coding-agents) — warn that harness loops amplify LLMs' worst tendencies and that "lights-off" software factories fail because LLMs cannot maintain codebase quality over time. The disagreement tracks a genuine empirical question: whether human oversight of AI-generated code can scale, or whether the feedback loops that made engineering a craft discipline are being quietly dismantled.
