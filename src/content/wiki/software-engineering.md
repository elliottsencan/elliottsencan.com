Software engineering is not a single discipline but a cluster of overlapping concerns: writing code that works, organizing it so others can understand it, shipping it reliably, and sustaining it over time. The sources here collectively surface a tension that has sharpened with AI tooling: the pressure to produce code fast sits in direct conflict with the judgment required to own what gets produced.

The craft dimension shows up across multiple angles. [Crafting Interpreters](/reading/2026-04/2026-04-30t231027-munificentcraftinginterpreters) is a canonical example of deep, deliberate implementation work — building two complete interpreters to understand language runtimes from first principles. At the design level, [the Single Responsibility Principle article](/reading/2026-06/2026-06-04t073318-single-responsibility-the-distorted-principle) argues the principle is routinely misread as "do one thing" when it actually means cohesive grouping under one accountable reason to change — over-granularizing classes violates the cognitive simplicity SRP exists to provide. [AI Likes Deep Modules](/reading/2026-05/2026-05-04t231343-ai-likes-deep-modules) extends this to module design: small interfaces hiding large implementations reduce complexity for humans and LLMs alike.

Process and judgment matter as much as structure. [The Unwritten Laws of Software Engineering](/reading/2026-06/2026-06-10t073045-the-unwritten-laws-of-software-engineering) distills hard-won rules from production incidents — roll back before debugging, treat every external dependency as a future outage. [Learn Algorithms for Interviews, Forget Them for Work](/reading/2026-04/2026-04-30t155134-learn-algorithms-for-interviews-forget-them-for-work) makes the related point that interview performance tests a narrow, trainable skill with weak correlation to production engineering, which requires reading tradeoffs and shipping incrementally against messy, unbounded real-world inputs. [The systemic decay of tech hiring](/reading/2026-06/2026-06-22t182141-the-systemic-decay-of-tech-hiring) traces how error asymmetry and Goodhart's Law have made the interview process itself dysfunctional.

Tooling shapes how engineers work. [Shell tricks](/reading/2026-04/2026-04-30t231815-shell-tricks-that-actually-make-life-easier-and-save-your) and [SSH key management](/reading/2026-05/2026-05-04t231548-using-ssh-keys-to-make-connectivity-simpler-and-secure) are foundational; [Reviewing Large Changes with Jujutsu](/reading/2026-05/2026-05-31t164252-reviewing-large-changes-with-jujutsu) and the [jj VCS](/reading/2026-05/2026-05-31t164554-jj-vcsjj) itself show that version control workflows remain an active area of craft. [Git log commands for auditing](/reading/2026-06/2026-06-18t024208-the-git-commands-i-run-before-reading-any-code) and [a consulting engineer's week-one Rails audit](/reading/2026-06/2026-06-18t090801-how-i-audit-a-legacy-rails-codebase-in-the-first-week) show that reading existing systems is a distinct, undervalued skill.

Testing and reliability surface repeatedly. [Playwright tests that survive UI refactors](/reading/2026-05/2026-05-05t135218-designing-playwright-tests-that-survive-ui-refactors) argues that test breakage is a coupling problem, not a selector problem — tests should bind to semantic roles, not DOM structure. [CI at scale](/reading/2026-04/2026-04-30t195531-what-ci-actually-looks-like-at-a-100-person-team) describes AI-assisted triage across 575K weekly jobs. [Approaching zero bugs](/reading/2026-05/2026-05-02t094735-approaching-zero-bugs) uses curl's vulnerability data to argue there is no measurable sign yet that AI-assisted static analysis is closing the gap on latent defects. [Testing a security tool like it can hurt people](/reading/2026-06/2026-06-11t024225-testing-a-security-tool-like-it-can-hurt-people) describes building deterministic assurance infrastructure that proves a system fails loudly when it overclaims certainty.

The AI question runs through almost every other concern. [Agentic Coding is a Trap](/reading/2026-04/2026-04-27t145041-agentic-coding-is-a-trap) argues full agentic workflows accelerate skill atrophy and create vendor dependency. [The perils of AI to the profession](/reading/2026-05/2026-05-14t223612-the-perils-of-ai-to-the-software-engineering-profession) calls vibe coding categorically incompatible with safety-critical systems. [Slow Mode](/reading/2026-05/2026-05-19t193626-slow-mode) proposes keeping the human in the loop at every step to trade short-term speed for genuine ownership. [The bottleneck was never the code](/reading/2026-05/2026-05-06t110728-the-bottleneck-was-never-the-code) reframes the question: agents make code-writing cheap, but the real bottleneck was always organizational coherence. [When code is cheap, does quality still matter?](/reading/2026-05/2026-05-22t091746-when-code-is-cheap-does-quality-still-matter) answers yes — LLMs generate polished technical debt faster than any individual engineer could. [The Coming Loop](/reading/2026-06/2026-06-23t161552-the-coming-loop) warns that agentic harnesses amplify LLMs' worst tendencies, producing defensive and opaque code that requires machine participation to maintain.

The tacit knowledge problem runs underneath all of this. [The Tacit Dimension](/reading/2026-05/2026-05-19t110710-the-tacit-dimension-why-your-best-engineers-cant-tell-you) draws on Polanyi to argue that the most valuable engineering expertise — pattern recognition, design intuition, unwritten conventions — is structurally inaccessible to AI and can only be transmitted through apprenticeship. [Why senior developers fail to communicate their expertise](/reading/2026-05/2026-05-13t060018-why-senior-developers-fail-to-communicate-their-expertise) makes the complementary point that engineers and business stakeholders speak different languages: complexity management versus uncertainty reduction. [Your onboarding is a hazing ritual](/reading/2026-05/2026-05-08t112608-your-onboarding-is-a-hazing-ritual-and-you-call-it-agile) shows what happens when institutional knowledge transfer breaks down at the organizational level.

Engineering judgment — when to optimize, what to cut, how to read a system — is the thread connecting all of it. [When impressive performance gains do not matter](/reading/2026-06/2026-06-30t185207-when-impressive-performance-gains-do-not-matter) is a pointed example: attention thresholds, discrete capacity increments, and pipeline backpressure can make an order-of-magnitude speedup irrelevant in practice. The idiot index applied to code makes the same point from the opposite direction — over-engineering signals low-value work. Good engineering is knowing which work is worth doing.
