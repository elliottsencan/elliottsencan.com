Software engineering is not a single discipline but a layered practice: writing code that works, structuring it so others can reason about it, deploying it reliably, and sustaining it over time as conditions change. The sources here cut across all of those layers, and a few recurring tensions emerge.

The most persistent tension is between speed and understanding. [Faye](https://larsfaye.com/articles/agentic-coding-is-a-trap) and [Gomes](https://abednegogomes.github.io/articles/docs/03_The_perils_of_artificial_intelligence_to_the_software_engineering_profession.html) both argue that shipping AI-generated code without comprehending it accelerates skill atrophy and is outright incompatible with safety-critical systems. [Aytas](https://yusufaytas.com/does-code-quality-still-matter) puts it precisely: AI lowers the cost of producing code but not the cost of owning it, and LLMs can generate polished technical debt faster than any individual engineer. [Zaides](https://www.manager.dev/newsletter/the-i-don-t-know-claude-wrote-this-pandemic) frames the same problem as cognitive ownership — engineers who let AI write code they cannot explain have surrendered something that matters. The counterpoint is not that AI is useless, but that it works best as a delegated tool rather than an autonomous author. [Millspaugh](https://blog.val.town/slow-mode) proposes a "Slow Mode" agent that keeps the programmer involved at every step, trading short-term throughput for genuine understanding.

Code structure is a related thread. [Go Monk](https://open.substack.com/pub/gomonk/p/ai-likes-deep-modules) argues that deep modules — small interfaces hiding large implementations — reduce complexity for both humans and LLMs. [Hari](https://medium.com/@kobihari/stop-creating-angular-component-monsters-ecb8a8852477) makes a similar case in the Angular context: components bloated with dozens of inputs should be refactored via composition so each concern stays encapsulated. [Teixeira](https://www.truehenrique.com/en/2021/10/27/single-responsibility-the-distorted-principle/) corrects a widespread misreading of the Single Responsibility Principle, arguing it means cohesive grouping under a single accountable responsibility, not granularizing to the point of incoherence.

Quality assurance is harder than it looks. [Stenberg](https://daniel.haxx.se/blog/2026/04/30/approaching-zero-bugs/) uses curl's vulnerability data to argue there is no measurable sign that even powerful AI-assisted static analysis is pushing open-source projects toward zero latent bugs. [Alba](https://www.mendral.com/blog/ci-at-scale) shows CI at PostHog's scale — 575K weekly jobs, 33M test executions — where an AI agent handles triage and opens fix PRs automatically, illustrating both the promise and the complexity of automated quality pipelines. Test design itself matters: [Currents](https://currents.dev/posts/designing-playwright-tests-that-survive-ui-refactors) argues Playwright suites break during refactors because they couple to DOM structure and CSS classes rather than semantic roles and accessible names. [How To Test Frontend](https://howtotestfrontend.com/resources/frontend-ai-generated-test-code-smells) documents 20+ recurring patterns AI tools introduce when generating frontend tests, including over-mocking and writing tests to match a buggy implementation rather than intended behavior.

Tooling and infrastructure concerns surface repeatedly. [Goodin](https://arstechnica.com/security/2026/03/supply-chain-attack-using-invisible-code-hits-github-and-other-repositories/) describes attackers encoding payloads in invisible Unicode variation-selector characters across 151 npm and GitHub packages, making them undetectable by reviewers and static analysis. [Galeone](https://pgaleone.eu/ai/2026/07/26/use-your-brain/) argues that strong CI/CD and code ownership are the structural responses — AI should amplify engineering discipline, not replace it. [Zaides](https://newsletter.manager.dev/p/the-unwritten-laws-of-software-engineering) distills production-incident lessons into rules like rolling back before debugging and treating every external dependency as a future outage.

Version control practice has its own depth. [Gesoff](https://ben.gesoff.uk/posts/reviewing-large-changes-with-jj/) describes a Jujutsu workflow for reviewing large pull requests by inserting an empty parent commit and squashing reviewed files into it, persisting progress without cognitive overhead. [Piechowski](https://piechowski.io/post/git-commands-before-reading-code/) outlines git log commands — churn hotspots, bus factor, bug clusters — that diagnose a codebase's risks before opening a single file.

The profession's knowledge problem is structural. [Cekrem](https://cekrem.github.io/posts/the-tacit-dimension/) draws on Polanyi to argue that the most valuable engineering expertise — pattern recognition, design intuition, unwritten conventions — is structurally inaccessible to AI and can only be transmitted through apprenticeship. [Nair](https://www.nair.sh/guides-and-opinions/communicating-your-expertise/why-senior-developers-fail-to-communicate-their-expertise) identifies a different gap: senior engineers communicate in terms of complexity management while the business thinks in terms of uncertainty reduction, and bridging that gap is the real challenge of expertise. [Brack](https://fagnerbrack.com/learn-algorithms-for-interviews-forget-them-for-work-c7dc5fe6cd3b) makes the hiring corollary: algorithm interviews test a narrow, trainable skill that weakly correlates with production performance, where real engineering means reading tradeoffs and shipping incrementally against messy, unbounded inputs.

Organizational dynamics shape outcomes as much as technical choices. [The Typical Set](https://www.thetypicalset.com/blog/thoughts-on-coding-agents) argues that the bottleneck was never the code — it was shared context, specification clarity, and management coherence, and coding agents amplify whatever alignment or misalignment an organization already has. [DHg](https://dhung.dev/blog/onboarding-hazing-ritual) identifies onboarding as a systemic failure point where dysfunction disguised as agile process sets new hires up to fail while remaining invisible to management. [Klepov](https://thoughtspile.github.io/2026/06/22/systemic-decay-of-hiring/) traces how well-intentioned engineers created dysfunctional interviews through error asymmetry and Goodhart's Law overfitting.

Performance optimization retains its own discipline. [Pastel](https://apas.tel/blog/optimizing-image-rs-blur) demonstrates a 5.9x speedup on Rust's image-rs blur function by replacing float arithmetic with integer accumulators and costly division with reciprocal multiplication. [Breck](https://blog.colinbreck.com/when-impressive-performance-gains-do-not-matter/) provides the counterweight: attention thresholds, discrete capacity increments, and pipeline backpressure explain why even order-of-magnitude gains often fail to change outcomes in practice.
