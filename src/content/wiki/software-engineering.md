Software engineering resists a single clean definition. The sources collected here pull it in at least three directions at once: the low-level craft of writing code that works; the organizational and procedural structures that determine how code gets built and shipped; and the harder question of what expertise, judgment, and quality mean when machines can generate code faster than humans can review it.

On craft: some things that look like engineering fundamentals turn out to be interview theater. [Learn Algorithms for Interviews, Forget Them for Work](/reading/2026-04/2026-04-30t155134-learn-algorithms-for-interviews-forget-them-for-work) argues that algorithm tests measure a narrow trainable skill that correlates weakly with production performance. Real engineering, by contrast, means reading tradeoffs and shipping systems that handle messy, unbounded inputs. [The Unwritten Laws of Software Engineering](/reading/2026-06/2026-06-10t073045-the-unwritten-laws-of-software-engineering) makes a similar move from principle to production, distilling seven hard-won rules from real incidents, including rolling back before debugging and treating every external dependency as a scheduled outage. [Single Responsibility, the Distorted Principle](/reading/2026-06/2026-06-04t073318-single-responsibility-the-distorted-principle) shows how a foundational design principle gets corrupted in practice: SRP means cohesive grouping under a single accountable responsibility, not atomizing every class to its smallest possible surface.

Structural and architectural choices compound over time. [AI Likes Deep Modules](/reading/2026-05/2026-05-04t231343-ai-likes-deep-modules) argues that small interfaces over large implementations reduce complexity for both human and machine readers. [A Better Way to Build Angular Components](/reading/2026-04/2026-04-30t232001-a-better-way-to-build-angular-components-from-inputs-to) applies the same logic to frontend components: input-bloated components should be refactored into directives and sub-components so that each concern stays encapsulated. At scale, organizational structure shapes what code even gets written. [What CI Actually Looks Like at a 100-Person Team](/reading/2026-04/2026-04-30t195531-what-ci-actually-looks-like-at-a-100-person-team) describes an AI-assisted CI triage system handling 575K weekly jobs at PostHog, automatically tracing flaky tests and opening fix PRs. [Designing Playwright Tests That Survive UI Refactors](/reading/2026-05/2026-05-05t135218-designing-playwright-tests-that-survive-ui-refactors) argues that test suites break not from poor selector choices but from coupling to implementation details rather than semantic roles.

Quality is the thread that holds these concerns together. [Approaching Zero Bugs](/reading/2026-05/2026-05-02t094735-approaching-zero-bugs) uses curl's vulnerability data to show that despite powerful AI-assisted static analysis, there is no measurable sign open-source projects are converging toward zero latent bugs. [When Code Is Cheap, Does Quality Still Matter?](/reading/2026-05/2026-05-22t091746-when-code-is-cheap-does-quality-still-matter) answers yes: AI lowers the cost of producing code but not the cost of owning it, and LLMs can generate polished technical debt faster than any individual engineer. [The Idiot Index for Code](/reading/2026-06/2026-06-22t000701-the-idiot-index-for-code) extends this into a ratio argument: bloated, over-engineered code is low-value work by definition.

The largest current fault line is between speed and understanding. [Agentic Coding is a Trap](/reading/2026-04/2026-04-27t145041-agentic-coding-is-a-trap) warns that full agentic workflows accelerate skill atrophy and invert developer priorities toward speed over comprehension. [The Perils of AI to the Software Engineering Profession](/reading/2026-05/2026-05-14t223612-the-perils-of-ai-to-the-software-engineering-profession) goes further, calling vibe coding categorically incompatible with safety-critical systems. [The Coming Loop](/reading/2026-06/2026-06-23t161552-the-coming-loop) warns that agentic harnesses amplify LLMs' worst tendencies, producing defensive opaque code and potentially creating codebases that require machine participation to maintain. [Slow Mode](/reading/2026-05/2026-05-19t193626-slow-mode) proposes the counter: an agent that teaches and plans alongside the programmer rather than autonomously looping. [Use Your Brain](/reading/2026-08/2026-08-05t072544-use-your-brain-engineering-standards-in-the-age-of-llms) frames the organizational response: strong CI/CD, code ownership, and engineering discipline let AI function as amplifier rather than replacement.

The tacit knowledge problem cuts across all of this. [The Tacit Dimension](/reading/2026-05/2026-05-19t110710-the-tacit-dimension-why-your-best-engineers-cant-tell-you) argues, drawing on Michael Polanyi, that the most valuable engineering expertise, pattern recognition and design intuition, is structurally inaccessible to AI tools and can only be transmitted through apprenticeship. [Why Senior Developers Fail to Communicate Their Expertise](/reading/2026-05/2026-05-13t060018-why-senior-developers-fail-to-communicate-their-expertise) locates the same gap in organizational communication: senior engineers speak in complexity management terms while the rest of the business thinks in uncertainty reduction terms. [The Bottleneck Was Never the Code](/reading/2026-05/2026-05-06t110728-the-bottleneck-was-never-the-code) synthesizes both: coding agents make individual code-writing cheap, but the real bottleneck was always shared context and specification clarity, and agents only amplify whatever alignment or misalignment the organization already has.

Onboarding surfaces a concrete version of this dysfunction. [Your Onboarding Is a Hazing Ritual](/reading/2026-05/2026-05-08t112608-your-onboarding-is-a-hazing-ritual-and-you-call-it-agile) documents how poor onboarding practices disguised as agile process systematically set new hires up to fail while making the problem invisible to management. [The Software Engineering War](/reading/2026-07/2026-07-07t170607-the-software-engineering-war) names the broader cultural split: engineers divide between builders who prioritize shipping fast with AI and keepers who insist on quality, and the split is as much a social fact as a technical one.

What holds the craft together, finally, is judgment about what matters. [When Impressive Performance Gains Do Not Matter](/reading/2026-06/2026-06-30t185207-when-impressive-performance-gains-do-not-matter) shows that order-of-magnitude improvements can be irrelevant when attention thresholds, capacity increments, and pipeline backpressure absorb them. Formal verification is gaining relevance here: [Formal Methods and the Future of Programming](/reading/2026-06/2026-06-15t021106-formal-methods-and-the-future-of-programming) argues that agentic coding has made proofs newly cost-effective by lowering the cost of writing them while creating demand for verification that tests alone cannot provide. Security does not get simpler either: [Supply-Chain Attack Using Invisible Unicode Code](/reading/2026-04/2026-04-30t231634-supply-chain-attack-using-invisible-code-hits-github-and) shows attackers encoding payloads in invisible Unicode variation-selector characters, undetectable by code review or static analysis, a reminder that the attack surface scales with the ecosystem.
