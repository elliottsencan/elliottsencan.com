Software engineering is not reducible to writing code. The sources gathered here cover a wide range of sub-disciplines — CI infrastructure, testing, version control, security, architecture, onboarding, formal methods, performance optimization — and the thread running through all of them is that technical execution depends on surrounding structures of knowledge, process, and judgment that tools alone cannot supply.

On the craft side, several sources address what good code actually looks like independent of who or what wrote it. The argument for deep modules — small interfaces hiding large implementations — holds that simplicity of interface is the primary unit of complexity management, and that this principle benefits both human readers and LLMs equally [AI Likes Deep Modules](/reading/2026-05/2026-05-04t231343-ai-likes-deep-modules). The Single Responsibility Principle is frequently misread as "do one thing" when it actually calls for cohesive grouping under a single accountable concern; over-granularizing classes produces the same cognitive overhead SRP was meant to eliminate [Single Responsibility, the Distorted Principle](/reading/2026-06/2026-06-04t073318-single-responsibility-the-distorted-principle). Angular component design illustrates the same failure mode at a framework level: components bloated with dozens of inputs should be decomposed into directives and sub-components that keep each concern encapsulated [A Better Way to Build Angular Components](/reading/2026-04/2026-04-30t232001-a-better-way-to-build-angular-components-from-inputs-to).

The question of what engineers actually need to know surfaces tension between interview culture and production reality. Algorithm interviews test a narrow, trainable skill that weakly predicts whether someone can read tradeoffs, ship incrementally, or build systems handling messy real-world inputs [Learn Algorithms for Interviews, Forget Them for Work](/reading/2026-04/2026-04-30t155134-learn-algorithms-for-interviews-forget-them-for-work). Hiring dysfunction compounds this: error asymmetry pushes interviews toward ever-harder tests, shared interviewer pools destroy accountability, and candidates overfit via Goodhart's Law [The systemic decay of tech hiring](/reading/2026-06/2026-06-22t182141-the-systemic-decay-of-tech-hiring).

Operational engineering — the unglamorous work of keeping systems running — gets sustained attention across several pieces. CI at scale means triaging 575K weekly jobs and 33M test executions; Mendral's AI agent ingests billions of log lines, traces flaky tests to root causes, and opens fix PRs automatically [What CI Actually Looks Like at a 100-Person Team](/reading/2026-04/2026-04-30t195531-what-ci-actually-looks-like-at-a-100-person-team). Playwright test suites break during UI refactors not because of bad selectors alone, but because tests couple to implementation details rather than stable semantic roles and accessible names [Designing Playwright Tests That Survive UI Refactors](/reading/2026-05/2026-05-05t135218-designing-playwright-tests-that-survive-ui-refactors). Seven production-hardened rules — including rolling back before debugging and treating every external dependency as a future outage — distill costly incident lessons into durable heuristics [The Unwritten Laws of Software Engineering](/reading/2026-06/2026-06-10t073045-the-unwritten-laws-of-software-engineering). Performance optimization is domain-specific: even order-of-magnitude gains often fail to change outcomes when attention thresholds, discrete capacity increments, or pipeline backpressure absorb the improvement before it reaches the user [When Impressive Performance Gains Do Not Matter](/reading/2026-06/2026-06-30t185207-when-impressive-performance-gains-do-not-matter).

Security is embedded in ordinary workflows in ways that are easy to miss. A supply-chain attack encoded payloads in invisible Unicode variation-selector characters across 151 malicious npm and GitHub packages — undetectable by code review or static analysis, executable at runtime [Supply-chain attack using invisible Unicode code](/reading/2026-04/2026-04-30t231634-supply-chain-attack-using-invisible-code-hits-github-and). Despite powerful new AI-assisted static analysis tools, curl's vulnerability age and bugfix-rate data show no measurable sign that open-source projects are approaching zero latent bugs [Approaching zero bugs?](/reading/2026-05/2026-05-02t094735-approaching-zero-bugs).

Knowledge transfer is where engineering organizations most visibly fail. Senior engineers communicate in terms of complexity management while the rest of the business thinks in terms of uncertainty reduction, and that translation gap costs more than any technical debt [Why Senior Developers Fail to Communicate Their Expertise](/reading/2026-05/2026-05-13t060018-why-senior-developers-fail-to-communicate-their-expertise). The most valuable engineering expertise — pattern recognition, unwritten conventions, design intuition — is structurally inaccessible to AI tools because it is tacit knowledge that can only be transmitted through apprenticeship [The Tacit Dimension](/reading/2026-05/2026-05-19t110710-the-tacit-dimension-why-your-best-engineers-cant-tell-you). Onboarding dysfunction compounds this: packed meeting calendars, same-sprint workloads from day one, and probation-enforced silence systematically set new hires up to fail while making the dysfunction invisible to management [Your Onboarding Is a Hazing Ritual](/reading/2026-05/2026-05-08t112608-your-onboarding-is-a-hazing-ritual-and-you-call-it-agile).

AI tooling runs through the entire collection as a forcing function that sharpens pre-existing questions rather than answering them. Coding agents make individual code-writing cheap, but the real bottleneck has always been organizational: shared context, specification clarity, and management coherence — and agents amplify whatever alignment or misalignment an organization already has [The bottleneck was never the code](/reading/2026-05/2026-05-06t110728-the-bottleneck-was-never-the-code). AI lowers the cost of producing code without lowering the cost of owning it; taste, judgment, and bounded prompting still matter because LLMs can generate polished, well-formatted technical debt faster than any individual engineer [When Code Is Cheap, Does Quality Still Matter?](/reading/2026-05/2026-05-22t091746-when-code-is-cheap-does-quality-still-matter). Full agentic workflows accelerate skill atrophy, invert developer priorities toward speed over understanding, and create vendor dependency — making the case for keeping LLMs as secondary delegation tools while staying hands-on with implementation [Agentic Coding is a Trap](/reading/2026-04/2026-04-27t145041-agentic-coding-is-a-trap). Agentic coding has also made formal methods newly cost-effective by both lowering the cost of writing proofs and creating urgent demand for verification that goes beyond what tests provide [Formal Methods and the Future of Programming](/reading/2026-06/2026-06-15t021106-formal-methods-and-the-future-of-programming). The engineers who cannot use AI effectively face five structural barriers: weak type systems, learned distrust of all generated code, org processes built for human-speed development, fear-driven resistance, and lack of agent-management training [Why Most Developers Can't Use AI Effectively](/reading/2026-05/2026-05-17t204925-why-most-developers-cant-use-ai-effectively). AI-generated frontend tests introduce recurring code smells — over-mocking, testing only happy paths, writing tests that match a buggy implementation rather than intended behavior — problems that require human judgment to detect [Code Smells when you get AI to write your Frontend Tests](/reading/2026-06/2026-06-22t185420-code-smells-when-you-get-ai-to-write-your-frontend-tests).
