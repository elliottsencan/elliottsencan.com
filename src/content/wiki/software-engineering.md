Software engineering resists a tidy definition because it encompasses both technical craft and organizational behavior. The sources here collectively pull on three threads: the principles that make software systems maintainable, the tooling that supports daily practice, and the growing pressure AI places on professional judgment.

On principles, a cluster of sources revisit foundational rules with fresh eyes. [Single Responsibility](/reading/2026-06/2026-06-04t073318-single-responsibility-the-distorted-principle) argues the principle is routinely misread as "do one thing" when it actually means cohesive grouping under one accountable owner — over-granularizing classes violates the cognitive simplicity SRP is meant to produce. [Deep modules](/reading/2026-05/2026-05-04t231343-ai-likes-deep-modules) offers a complementary frame: small interfaces hiding large implementations reduce complexity for both human readers and LLMs. [The unwritten laws](/reading/2026-06/2026-06-10t073045-the-unwritten-laws-of-software-engineering) ground these abstractions in production reality — roll back before debugging, treat every external dependency as a future outage. Taken together, they describe an engineering ethic that prizes readability and bounded failure over cleverness.

Code quality under AI pressure is the most contested thread. Several sources argue that cheaper code generation does not reduce the cost of owning what gets generated. [When Code Is Cheap](/reading/2026-05/2026-05-22t091746-when-code-is-cheap-does-quality-still-matter) puts it plainly: LLMs can produce polished technical debt faster than any individual engineer. [The Perils of AI to the Software Engineering Profession](/reading/2026-05/2026-05-14t223612-the-perils-of-ai-to-the-software-engineering-profession) goes further, treating "vibe coding" as categorically incompatible with safety-critical systems. [Use Your Brain](/reading/2026-08/2026-08-05t072544-use-your-brain-engineering-standards-in-the-age-of-llms) calls for strong CI/CD and code ownership as correctives to the custodian mindset AI promotes. Against this, [the bottleneck was never the code](/reading/2026-05/2026-05-06t110728-the-bottleneck-was-never-the-code) shifts the frame: the real constraint has always been organizational — shared context, specification clarity, coherent management — and agents amplify whatever alignment or misalignment already exists.

Agentic workflows sharpened that tension in 2025-2026. [Agentic Coding is a Trap](/reading/2026-04/2026-04-27t145041-agentic-coding-is-a-trap) argues that full automation accelerates skill atrophy and inverts developer priorities from understanding toward speed. [Slow Mode](/reading/2026-05/2026-05-19t193626-slow-mode) proposes keeping the human involved at every planning and implementation step, trading short-term throughput for genuine ownership. [The Coming Loop](/reading/2026-06/2026-06-23t161552-the-coming-loop) warns that harness orchestration amplifies LLMs' worst tendencies — defensive, opaque code — and risks producing codebases that require machine participation to maintain. [Lights-off software factories](/reading/2026-07/2026-07-23t215330-humanlayeradvanced-context-engineering-for-coding-agents) fail, the argument goes, because no harness engineering can fix the underlying training problem that prevents LLMs from maintaining quality over time.

Testing surfaces the same tension at smaller scale. [Playwright tests](/reading/2026-05/2026-05-05t135218-designing-playwright-tests-that-survive-ui-refactors) break during refactors not from bad selector choices alone but from coupling to implementation details instead of stable semantic roles. [AI-generated test code smells](/reading/2026-06/2026-06-22t185420-code-smells-when-you-get-ai-to-write-your-frontend-tests) catalogs the patterns AI introduces: over-mocking, happy-path-only coverage, tests written to match a buggy implementation. [CI at scale](/reading/2026-04/2026-04-30t195531-what-ci-actually-looks-like-at-a-100-person-team) shows one response to the testing problem at PostHog — an AI triage agent ingesting 33 million weekly test executions and opening fix PRs for flaky failures. Whether that represents engineering progress or further abstraction away from understanding is exactly the disagreement these sources circle.

Bug density resists easy optimism. [Approaching zero bugs](/reading/2026-05/2026-05-02t094735-approaching-zero-bugs) uses curl's vulnerability age data to argue there is no measurable evidence that even powerful AI-assisted static analysis is driving open-source projects toward zero latent bugs. [Formal methods](/reading/2026-06/2026-06-15t021106-formal-methods-and-the-future-of-programming) offers a contrarian read: agentic coding may finally make verification cost-effective precisely because it lowers the cost of writing proofs while raising demand for guarantees that tests alone cannot provide.

Tooling practice rounds out the picture. [Shell tricks](/reading/2026-04/2026-04-30t231815-shell-tricks-that-actually-make-life-easier-and-save-your), [SSH keys](/reading/2026-05/2026-05-04t231548-using-ssh-keys-to-make-connectivity-simpler-and-secure), [container filesystem internals](/reading/2026-05/2026-05-04t231858-how-container-filesystem-works-building-a-docker-like), [git log diagnostics](/reading/2026-06/2026-06-18t024208-the-git-commands-i-run-before-reading-any-code), and [Jujutsu's review workflow](/reading/2026-05/2026-05-31t164252-reviewing-large-changes-with-jujutsu) all argue, implicitly, that close familiarity with the tools beneath the abstraction still matters. [Crafting Interpreters](/reading/2026-04/2026-04-30t231027-munificentcraftinginterpreters) exemplifies that ethos taken to an extreme: building two complete language runtimes to understand how interpretation actually works.

Hiring and onboarding expose how engineering culture replicates (or fails to replicate) its own values. [Algorithm interviews](/reading/2026-04/2026-04-30t155134-learn-algorithms-for-interviews-forget-them-for-work) test a narrow, trainable skill with weak correlation to production performance. [Systemic decay of tech hiring](/reading/2026-06/2026-06-22t182141-the-systemic-decay-of-tech-hiring) traces how error-asymmetric evaluation, shared interviewer pools, and Goodhart's Law together produce dysfunctional processes nobody designed. [Onboarding as hazing ritual](/reading/2026-05/2026-05-08t112608-your-onboarding-is-a-hazing-ritual-and-you-call-it-agile) shows the same dysfunction at the integration stage. And [tacit knowledge](/reading/2026-05/2026-05-19t110710-the-tacit-dimension-why-your-best-engineers-cant-tell-you) argues that the most valuable engineering expertise — pattern recognition, design intuition, unwritten convention — is structurally inaccessible to AI and can only be transmitted through apprenticeship.

The field is not converging on a settled answer to any of these questions. What does emerge across sources is a shared diagnosis: software engineering's hard problems were never primarily about the speed of code production, and making that production faster has not changed which problems are hard.
