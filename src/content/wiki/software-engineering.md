Software engineering is rarely just about writing code. The sources here converge on a recurring tension: speed is increasingly cheap, but understanding, ownership, and judgment are not.

The most direct statement of that tension comes from [Lars Faye](/reading/2026-04/2026-04-27t145041-agentic-coding-is-a-trap), who argues that full agentic coding workflows invert developer priorities toward shipping over comprehending, causing skill atrophy and vendor lock-in to AI providers. [Pete Millspaugh](/reading/2026-05/2026-05-19t193626-slow-mode) responds to the same problem with a design proposal: a "Slow Mode" agent that forces the programmer to stay involved at each step, trading short-term velocity for genuine code ownership. [Anton Zaides](/reading/2026-08/2026-08-31t131721-the-i-dont-know-claude-wrote-this-pandemic) frames the failure mode bluntly: engineers who ship AI-generated code without understanding it are surrendering cognitive ownership, not exercising it.

The argument about what AI changes extends further. [Yusuf Aytas](/reading/2026-05/2026-05-22t091746-when-code-is-cheap-does-quality-still-matter) observes that AI lowers the cost of producing code but not the cost of owning it — LLMs can generate polished technical debt faster than any individual developer ever could. [Paolo Galeone](/reading/2026-08/2026-08-05t072544-use-your-brain-engineering-standards-in-the-age-of-llms) calls the result a "custodian" mindset and argues that strong CI/CD, code ownership, and engineering discipline are what keep AI as an amplifier rather than a replacement for thought. [Abednego Gomes](/reading/2026-05/2026-05-14t223612-the-perils-of-ai-to-the-software-engineering-profession) puts the hardest constraint on the table: reckless AI-generated code is categorically incompatible with safety-critical systems.

Design quality is the other half of that argument. [Go Monk](/reading/2026-05/2026-05-04t231343-ai-likes-deep-modules) makes the case that deep modules — small interfaces hiding large implementations — reduce complexity for humans and LLMs alike, contrasting shallow versus deep Go examples. [Henrique Teixeira](/reading/2026-06/2026-06-04t073318-single-responsibility-the-distorted-principle) argues that the Single Responsibility Principle is widely misread as "do one thing" when it actually means cohesive grouping under a single accountable responsibility, and that over-granularizing violates the cognitive simplicity SRP is meant to provide. [Armin Ronacher](/reading/2026-06/2026-06-23t161552-the-coming-loop) adds a warning about orchestration harnesses: outer loops amplify LLMs' worst tendencies, producing defensive, opaque code and risking codebases that require machine participation to maintain.

Process and tooling questions run through many of the pieces. [Sam Alba](/reading/2026-04/2026-04-30t195531-what-ci-actually-looks-like-at-a-100-person-team) describes what continuous integration looks like at real scale — 575K weekly jobs, with an AI agent tracing flaky tests to root causes and opening fix PRs automatically. [Anton Zaides's unwritten laws](/reading/2026-06/2026-06-10t073045-the-unwritten-laws-of-software-engineering) distill production hard-won rules: roll back before debugging, treat every external dependency as a future outage. [Ben Gesoff](/reading/2026-05/2026-05-31t164252-reviewing-large-changes-with-jujutsu) shows a concrete workflow for reviewing large changes in Jujutsu by inserting empty parent commits and squashing files as review progresses, persisting work in version control rather than stashes.

Security surfaces as a design concern rather than a separate discipline. [Dan Goodin](/reading/2026-04/2026-04-30t231634-supply-chain-attack-using-invisible-code-hits-github-and) reports 151 malicious npm and GitHub packages encoding payloads in invisible Unicode variation-selector characters — undetectable by code reviewers and static analysis tools — a concrete reminder that the review process itself is an attack surface.

Two sources address what engineering expertise actually is and how it gets communicated. [Tuhin Nair](/reading/2026-05/2026-05-13t060018-why-senior-developers-fail-to-communicate-their-expertise) argues that senior developers communicate in terms of complexity management while the rest of the business thinks in terms of uncertainty reduction, and that bridging that gap is the real challenge of expertise. [cekrem](/reading/2026-05/2026-05-19t110710-the-tacit-dimension-why-your-best-engineers-cant-tell-you) draws on Michael Polanyi's philosophy of tacit knowledge to argue that the most valuable engineering skill — pattern recognition, design intuition, unwritten convention — is structurally inaccessible to AI and can only be transmitted through apprenticeship.

The hiring process adds its own distortions. [Fagner Brack](/reading/2026-04/2026-04-30t155134-learn-algorithms-for-interviews-forget-them-for-work) argues that algorithm interviews test a narrow trainable skill that weakly correlates with production performance; real engineering requires reading tradeoffs and shipping incrementally. [Vladimir Klepov](/reading/2026-06/2026-06-22t182141-the-systemic-decay-of-tech-hiring) traces how error asymmetry, shared interviewer pools, and Goodhart's Law have made the interview process systematically dysfunctional.

Onboarding sits at the same junction. [DHg](/reading/2026-05/2026-05-08t112608-your-onboarding-is-a-hazing-ritual-and-you-call-it-agile) describes how poor onboarding practices — packed meeting schedules, same-sprint workloads from day one, probation-enforced silence — set new hires up to fail while making the dysfunction invisible to management.

Taken together, these sources make a consistent argument: the bottleneck in software engineering has never been the volume of code produced. [The Typical Set](/reading/2026-05/2026-05-06t110728-the-bottleneck-was-never-the-code) puts it directly — coding agents make individual code-writing cheap, but shared context, specification clarity, and organizational coherence remain the actual constraints, and agents amplify whatever alignment or misalignment already exists.
