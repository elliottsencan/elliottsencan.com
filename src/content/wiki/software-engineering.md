The discipline sits at the intersection of technical rigor and organizational behavior, and what makes software engineering hard is rarely the algorithms. [Fagner Brack's critique of algorithm interviews](/reading/2026-04/2026-04-30t155134-learn-algorithms-for-interviews-forget-them-for-work) is precise on this: the skills tested in whiteboard rounds — optimal sorting, graph traversal under artificial constraints — correlate weakly with production engineering, which demands reading tradeoffs, shipping incrementally, and building systems that handle unbounded real-world input.

Design principles share similar distortion problems. The Single Responsibility Principle is routinely misread as "do only one thing," when Robert Martin's actual formulation concerns cohesive grouping under a single accountable responsibility. [Henrique Teixeira argues](/reading/2026-06/2026-06-04t073318-single-responsibility-the-distorted-principle) that over-granularizing classes violates the cognitive simplicity SRP exists to provide. The same instinct toward compression appears in the argument for deep modules: [Go Monk](/reading/2026-05/2026-05-04t231343-ai-likes-deep-modules) contends that small interfaces hiding large implementations reduce complexity for both human readers and LLMs.

Code quality is under particular pressure from AI tooling. Several sources converge on the same concern from different directions. [Lars Faye](/reading/2026-04/2026-04-27t145041-agentic-coding-is-a-trap) argues that full agentic workflows accelerate skill atrophy and invert developer priorities toward speed over understanding, creating vendor dependency in the process. [Abednego Gomes](/reading/2026-05/2026-05-14t223612-the-perils-of-ai-to-the-software-engineering-profession) is more categorical: shipping AI-generated code without review is incompatible with safety-critical systems and erodes the craft across the board. [Yusuf Aytas](/reading/2026-05/2026-05-22t091746-when-code-is-cheap-does-quality-still-matter) reframes the economics: AI lowers the cost of producing code but not the cost of owning it, and LLMs can generate polished technical debt faster than any individual engineer. [Anton Zaides](/reading/2026-08/2026-08-31t131721-the-i-dont-know-claude-wrote-this-pandemic) calls the result cognitive surrender — engineers who accept AI output without understanding it forfeit ownership of the codebase.

The organizational dimension is equally important. [The Typical Set](/reading/2026-05/2026-05-06t110728-the-bottleneck-was-never-the-code) argues the real bottleneck was never code-writing but shared context, specification clarity, and management coherence — and agents amplify existing misalignment. [Dhung's onboarding critique](/reading/2026-05/2026-05-08t112608-your-onboarding-is-a-hazing-ritual-and-you-call-it-agile) shows how dysfunction compounds when new engineers are handed same-sprint workloads from day one under the cover of agile language. [Tuhin Nair](/reading/2026-05/2026-05-13t060018-why-senior-developers-fail-to-communicate-their-expertise) identifies a communication gap that compounds this: senior engineers reason in terms of complexity management while the business thinks in terms of uncertainty reduction, and the failure to bridge that gap is its own engineering liability.

Practical engineering discipline surfaces across multiple sources. [Anton Zaides's unwritten laws](/reading/2026-06/2026-06-10t073045-the-unwritten-laws-of-software-engineering) — roll back before debugging, treat every external dependency as a future outage — are distilled from production incidents. [Sam Alba](/reading/2026-04/2026-04-30t195531-what-ci-actually-looks-like-at-a-100-person-team) shows what CI rigor looks like at scale: 575,000 weekly jobs and 33 million test executions at PostHog, triaged by an AI agent that traces flaky tests to root causes and opens fix PRs. [The Currents team](/reading/2026-05/2026-05-05t135218-designing-playwright-tests-that-survive-ui-refactors) argues that test suites break during refactors not from bad selector choices alone but from coupling to implementation details rather than stable semantic roles. [Paolo Galeone](/reading/2026-08/2026-08-05t072544-use-your-brain-engineering-standards-in-the-age-of-llms) calls for strong CI/CD and code ownership as the discipline that keeps AI an amplifier rather than a replacement for judgment.

Security is not peripheral to engineering practice. [Dan Goodin's supply-chain attack report](/reading/2026-04/2026-04-30t231634-supply-chain-attack-using-invisible-code-hits-github-and) describes 151 malicious npm and GitHub packages encoding payloads in invisible Unicode variation-selector characters, undetectable by code review or static analysis. [Daniel Stenberg](/reading/2026-05/2026-05-02t094735-approaching-zero-bugs) uses curl's vulnerability data to argue there is no measurable sign yet that AI-assisted static analysis is pushing open-source projects toward zero latent bugs.

Version control and tooling shape how engineers actually work. [Ben Gesoff](/reading/2026-05/2026-05-31t164252-reviewing-large-changes-with-jujutsu) describes a Jujutsu workflow for reviewing large pull requests by squashing reviewed files into an inserted parent commit, persisting progress in version control without git stash overhead. [Ally Piechowski](/reading/2026-06/2026-06-18t024208-the-git-commands-i-run-before-reading-any-code) shows how git log commands diagnosing churn hotspots, bus factor, and bug clusters can characterize a codebase's risks before opening a single file.

Two tensions run through the sources without clean resolution. One is between shipping speed and craft: [Anton Zaides's builders-vs-keepers framing](/reading/2026-07/2026-07-07t170607-the-software-engineering-war) names the split explicitly, and notes that where an engineer lands often depends on who is in the room. The other is between AI assistance and genuine understanding: [Pete Millspaugh's Slow Mode proposal](/reading/2026-05/2026-05-19t193626-slow-mode) argues for AI agents that teach and involve the programmer at every step rather than looping autonomously, trading short-term productivity for long-term ownership. [Armin Ronacher](/reading/2026-06/2026-06-23t161552-the-coming-loop) warns that agent harness loops risk producing codebases that require machine participation to maintain, raising questions about human oversight that the profession has not answered.
