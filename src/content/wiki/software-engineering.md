Software engineering is less a single discipline than a constellation of overlapping concerns: writing code that works, maintaining it over time, coordinating across teams, and making judgment calls that no automated tool has yet reliably internalized. The sources here span that full range, and several recurring tensions emerge.

The most active debate is over what AI assistance does to the craft itself. [Lars Faye](/reading/2026-04/2026-04-27t145041-agentic-coding-is-a-trap) argues that fully agentic coding workflows erode developer skill and shift priorities toward speed over understanding, creating vendor lock-in in the process. [Abednego Gomes](/reading/2026-05/2026-05-14t223612-the-perils-of-ai-to-the-software-engineering-profession) makes a sharper version of the same claim: shipping AI-generated code without review is reckless by definition, and categorically incompatible with safety-critical systems. [Yusuf Aytas](/reading/2026-05/2026-05-22t091746-when-code-is-cheap-does-quality-still-matter) adds that AI lowers the cost of producing code but not the cost of owning it — LLMs can generate well-formatted technical debt faster than any individual engineer ever could. [Pete Millspaugh](/reading/2026-05/2026-05-19t193626-slow-mode) proposes a middle path: a "Slow Mode" agent that keeps humans involved at every planning step, trading short-term velocity for long-term ownership.

Not everyone accepts that the bottleneck is the code itself. [The Typical Set](/reading/2026-05/2026-05-06t110728-the-bottleneck-was-never-the-code) argues the real constraints have always been organizational — shared context, specification clarity, management coherence — and that coding agents amplify whatever alignment or misalignment an organization already has. [Werner Vogels](/reading/2026-06/2026-06-30t173037-a-return-to-two-pizza-culture) takes a more optimistic view: AI has compressed prototyping enough to warrant changing the order of operations in product development, building before writing the spec rather than after.

Design principles show up repeatedly as the stable substrate beneath all of this. [Go Monk](/reading/2026-05/2026-05-04t231343-ai-likes-deep-modules) argues that deep modules — small interfaces hiding large implementations — reduce complexity for both humans and LLMs. [Henrique Teixeira](/reading/2026-06/2026-06-04t073318-single-responsibility-the-distorted-principle) corrects the common misreading of the Single Responsibility Principle, arguing that over-granularizing classes violates the cognitive simplicity SRP was meant to provide. [Kobi Hari](/reading/2026-04/2026-04-30t232001-a-better-way-to-build-angular-components-from-inputs-to) extends the same logic to Angular components, arguing that the Composite Components pattern keeps APIs clean and concerns encapsulated. [Matt Smith](/reading/2026-07/2026-07-16t043206-i-stopped-destructuring-everything) applies it to JavaScript idioms: reflexive destructuring optimizes for writing rather than reading, discarding the object reference that carries useful context.

Testing and CI are persistent operational concerns. [Fagner Brack](/reading/2026-04/2026-04-30t155134-learn-algorithms-for-interviews-forget-them-for-work) argues that algorithm interviews test a narrow, trainable skill that weakly correlates with production performance; real engineering requires reading tradeoffs and handling messy, unbounded inputs. [Sam Alba](/reading/2026-04/2026-04-30t195531-what-ci-actually-looks-like-at-a-100-person-team) shows what CI at scale actually looks like — 575K weekly jobs handled by an AI triage agent that traces flaky tests to root causes and opens fix PRs automatically. The Playwright articles from [Currents](/reading/2026-05/2026-05-05t135218-designing-playwright-tests-that-survive-ui-refactors) establish that test brittleness comes from coupling to implementation details rather than semantic roles. AI introduces its own testing pathologies: [How To Test Frontend](/reading/2026-06/2026-06-22t185420-code-smells-when-you-get-ai-to-write-your-frontend-tests) documents over 20 recurring patterns AI tools produce, including over-mocking, happy-path-only coverage, and tests written to match a buggy implementation rather than intended behavior.

Security is a layer that sits underneath all of this. [Dan Goodin](/reading/2026-04/2026-04-30t231634-supply-chain-attack-using-invisible-code-hits-github-and) reports on 151 malicious npm and GitHub packages encoding payloads in invisible Unicode variation-selector characters, undetectable by code reviewers and static analysis alike. [Daniel Stenberg](/reading/2026-05/2026-05-02t094735-approaching-zero-bugs) uses curl's own vulnerability data to argue there is no measurable sign yet that open-source projects are approaching zero latent bugs, even with powerful new AI-assisted analysis tools.

Tooling debates continue in parallel. [Ben Gesoff](/reading/2026-05/2026-05-31t164252-reviewing-large-changes-with-jujutsu) and the [jj-vcs project](/reading/2026-05/2026-05-31t164554-jj-vcsjj) offer Jujutsu as a Git-compatible VCS that handles conflicts as first-class objects and auto-commits working state. [Christian Hofstede-Kuhn](/reading/2026-04/2026-04-30t231815-shell-tricks-that-actually-make-life-easier-and-save-your) covers underused shell safeguards. [Ally Piechowski](/reading/2026-06/2026-06-18t024208-the-git-commands-i-run-before-reading-any-code) details git log queries that diagnose a codebase's churn, bus factor, and bug clusters before opening a single file.

The profession's social and organizational layer surfaces in several places. [Anton Zaides](/reading/2026-06/2026-06-10t073045-the-unwritten-laws-of-software-engineering) distills hard-won rules from production incidents. [DHg](/reading/2026-05/2026-05-08t112608-your-onboarding-is-a-hazing-ritual-and-you-call-it-agile) argues that dysfunctional onboarding disguised as agile process systematically sets new hires up to fail. [Tuhin Nair](/reading/2026-05/2026-05-13t060018-why-senior-developers-fail-to-communicate-their-expertise) locates a persistent gap: senior engineers communicate in terms of complexity management while the rest of the business thinks in terms of uncertainty reduction. [cekrem](/reading/2026-05/2026-05-19t110710-the-tacit-dimension-why-your-best-engineers-cant-tell-you) draws on Polanyi to argue that the most valuable engineering expertise — pattern recognition, design intuition, unwritten conventions — is structurally inaccessible to AI tools and can only be transmitted through apprenticeship.

Taken together, these sources suggest that the discipline is under pressure from two directions at once: AI tooling that raises output volume while potentially undermining the judgment that gives that output value, and organizational dynamics that have always resisted easy fixes regardless of what the tools can do.
