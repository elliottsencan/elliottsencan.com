Software engineering is the discipline of building systems that work reliably, stay maintainable over time, and serve actual human needs. The sources collected here span a wide range: shell scripting, CI at scale, version control workflows, testing strategy, component design, security, and the growing question of what role AI plays in all of it. A unifying thread runs through nearly all of them: producing code is cheap; owning it is expensive.

The cheapening of code production is the defining pressure on the profession right now. [Yusuf Aytas](/reading/2026-05/2026-05-22t091746-when-code-is-cheap-does-quality-still-matter) makes the point directly: AI lowers the marginal cost of generating a function or a module, but the maintenance cost of that code lands on a team that must read, debug, and extend it. [Lars Faye](/reading/2026-04/2026-04-27t145041-agentic-coding-is-a-trap) adds that fully autonomous agentic workflows accelerate skill atrophy and create vendor dependency — LLMs work better as delegation tools than as autonomous replacements for implementation. [Abednego Gomes](/reading/2026-05/2026-05-14t223612-the-perils-of-ai-to-the-software-engineering-profession) goes further, arguing that shipping unreviewed AI-generated code is categorically incompatible with safety-critical software. [Armin Ronacher](/reading/2026-06/2026-06-23t161552-the-coming-loop) warns that harness-driven agent loops amplify LLMs' tendency to produce defensive, opaque code, risking codebases that require machine participation to maintain. [Dex Horthy](/reading/2026-07/2026-07-23t215330-humanlayeradvanced-context-engineering-for-coding-agents) argues this is a fundamental training limitation, not a tooling problem that better harnesses can fix.

Skill and judgment remain irreplaceable on several fronts. [The tacit dimension essay](/reading/2026-05/2026-05-19t110710-the-tacit-dimension-why-your-best-engineers-cant-tell-you) draws on Michael Polanyi to argue that the most valuable engineering expertise — pattern recognition, design intuition, unwritten conventions — is structurally inaccessible to AI and can only be transmitted through apprenticeship. [Tuhin Nair](/reading/2026-05/2026-05-13t060018-why-senior-developers-fail-to-communicate-their-expertise) identifies a different gap: senior developers communicate in terms of complexity management while business stakeholders think in terms of uncertainty reduction, and bridging that translation is its own engineering skill. [Paolo Galeone](/reading/2026-08/2026-08-05t072544-use-your-brain-engineering-standards-in-the-age-of-llms) argues that strong CI/CD pipelines and genuine code ownership are the countermeasures, using AI as an amplifier rather than a crutch. [Pete Millspaugh](/reading/2026-05/2026-05-19t193626-slow-mode) proposes a deliberate "Slow Mode" agent that keeps the human involved at every step, trading short-term output for long-term understanding.

Good design principles still apply regardless of who or what writes the code. [Go Monk](/reading/2026-05/2026-05-04t231343-ai-likes-deep-modules) argues that deep modules — small interfaces hiding large implementations — reduce complexity for both humans and LLMs. [Henrique Teixeira](/reading/2026-06/2026-06-04t073318-single-responsibility-the-distorted-principle) corrects the common misreading of the Single Responsibility Principle: it means cohesive grouping under one accountability, not splitting every behavior into its own class. [Kobi Hari](/reading/2026-04/2026-04-30t232001-a-better-way-to-build-angular-components-from-inputs-to) makes a parallel argument for Angular components, advocating Composite Components over input-bloated monoliths. [Anton Zaides](/reading/2026-06/2026-06-10t073045-the-unwritten-laws-of-software-engineering) distills seven production-hardened rules, including rolling back before debugging and treating every external dependency as a future outage.

Testing is one concrete area where discipline matters most. [Currents](/reading/2026-05/2026-05-05t135218-designing-playwright-tests-that-survive-ui-refactors) argues that Playwright suites break during refactors because tests couple to implementation details rather than semantic roles. [Sam Alba](/reading/2026-04/2026-04-30t195531-what-ci-actually-looks-like-at-a-100-person-team) shows the scale this can reach: 575K weekly CI jobs at PostHog, where an AI triage agent ingests billions of log lines and opens fix PRs automatically. [Daniel Stenberg](/reading/2026-05/2026-05-02t094735-approaching-zero-bugs) uses curl's own vulnerability data to temper optimism — despite powerful new static analysis tools, there is no measurable sign yet that open-source projects are approaching zero latent bugs.

Security intersects with design in subtle ways. [Dan Goodin](/reading/2026-04/2026-04-30t231634-supply-chain-attack-using-invisible-code-hits-github-and) reports that attackers encoded payloads in invisible Unicode variation-selector characters — undetectable by code review and static analysis — across 151 npm and GitHub packages, a reminder that supply-chain hygiene is an engineering concern, not just an ops one.

Version control and tooling represent the operational layer. [Jujutsu](/reading/2026-05/2026-05-31t164554-jj-vcsjj) offers a Git-compatible system that auto-commits the working copy and treats conflicts as first-class objects. [Ben Gesoff](/reading/2026-05/2026-05-31t164252-reviewing-large-changes-with-jujutsu) shows a concrete workflow: duplicate a large change, insert an empty parent commit, and squash files into it as you review, persisting progress without stash overhead. [Ally Piechowski](/reading/2026-06/2026-06-18t024208-the-git-commands-i-run-before-reading-any-code) surfaces five git log commands that diagnose churn hotspots, bus factor, and bug clusters before reading a single file.

The profession is also under structural pressure. [Fagner Brack](/reading/2026-04/2026-04-30t155134-learn-algorithms-for-interviews-forget-them-for-work) argues that algorithm interview culture tests a narrow trainable skill that correlates weakly with production performance. [Vladimir Klepov](/reading/2026-06/2026-06-22t182141-the-systemic-decay-of-tech-hiring) traces how error asymmetry and shared interviewer pools have created dysfunctional hiring loops that candidates game through Goodhart's Law. [DHg](/reading/2026-05/2026-05-08t112608-your-onboarding-is-a-hazing-ritual-and-you-call-it-agile) argues that poor onboarding disguised as agile process systematically sets new engineers up to fail while making the dysfunction invisible to management.

The tension between shipping fast and building well is not new, but AI has sharpened it. [Anton Zaides](/reading/2026-07/2026-07-07t170607-the-software-engineering-war) describes a split between "builders" who prioritize speed and "keepers" who insist on quality, and notes that where any given engineer stands depends as much on organizational context as on principled belief. [The Typical Set](/reading/2026-05/2026-05-06t110728-the-bottleneck-was-never-the-code) frames the deeper issue: the bottleneck was never code-writing speed. It was shared context, specification clarity, and organizational alignment. Agents amplify whatever alignment — or misalignment — already exists.
