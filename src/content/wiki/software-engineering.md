Software engineering sits at the intersection of technical craft and organizational behavior. The sources here collectively resist any single thesis, but a through-line emerges: AI tooling has lowered the cost of producing code while leaving unchanged, or even raising, the cost of owning it.

The quality question is live and contested. [Yusuf Aytas](/reading/2026-05/2026-05-22t091746-when-code-is-cheap-does-quality-still-matter) argues that LLMs can generate polished, well-formatted technical debt faster than any individual engineer ever could, making taste and judgment more important, not less. [Lars Faye](/reading/2026-04/2026-04-27t145041-agentic-coding-is-a-trap) makes a sharper claim: full agentic workflows accelerate skill atrophy and invert developer priorities toward speed over understanding, creating vendor dependency in the process. [Abednego Gomes](/reading/2026-05/2026-05-14t223612-the-perils-of-ai-to-the-software-engineering-profession) adds that shipping AI-generated code without review is categorically incompatible with safety-critical systems. Against this, [The Typical Set](/reading/2026-05/2026-05-06t110728-the-bottleneck-was-never-the-code) argues the bottleneck was never the code itself but organizational alignment, shared context, and specification clarity — and coding agents simply amplify whatever coherence or dysfunction already exists. [Armin Ronacher](/reading/2026-06/2026-06-23t161552-the-coming-loop) warns that agent harness loops risk producing defensive, opaque codebases that require machine participation to maintain, raising urgent questions about human oversight.

Design principles sit closer to the center of the craft conversation. [Go Monk](/reading/2026-05/2026-05-04t231343-ai-likes-deep-modules) draws on John Ousterhout's deep module concept to argue that small interfaces hiding large implementations reduce complexity for both humans and LLMs. [Henrique Teixeira](/reading/2026-06/2026-06-04t073318-single-responsibility-the-distorted-principle) argues the Single Responsibility Principle is widely misread as "do only one thing" when it actually means cohesive grouping under a single accountable responsibility — and that over-granularizing violates the cognitive simplicity SRP is meant to provide. [Kobi Hari](/reading/2026-04/2026-04-30t232001-a-better-way-to-build-angular-components-from-inputs-to) applies similar reasoning to Angular components, arguing that bloated input-heavy components should be refactored via the Composite Components pattern so each concern stays encapsulated.

Testing cuts through several sources. [Currents Team](/reading/2026-05/2026-05-05t135218-designing-playwright-tests-that-survive-ui-refactors) argues Playwright suites break during refactors not because of bad selectors but because tests couple to implementation details rather than semantic roles. [How To Test Frontend](/reading/2026-06/2026-06-22t185420-code-smells-when-you-get-ai-to-write-your-frontend-tests) documents over twenty recurring patterns AI tools introduce in generated tests, including over-mocking and writing tests to match a buggy implementation rather than intended behaviour. [Imbue](/reading/2026-06/2026-06-23t212958-how-ai-code-review-can-make-correct-code-worse) found that weaker fixer agents in an AI review pipeline "overreach" beyond review scope and break correct code, with softer fixer instructions eliminating catastrophic regressions. [Daniel Stenberg](/reading/2026-05/2026-05-02t094735-approaching-zero-bugs) uses curl's vulnerability data to argue there is no measurable sign yet that AI-assisted static analysis is pushing open-source projects toward zero latent bugs.

Organizational and human dimensions recur. [Anton Zaides at manager.dev](/reading/2026-06/2026-06-10t073045-the-unwritten-laws-of-software-engineering) distills hard-won production rules including rolling back before debugging and treating every external dependency as a future outage. [Anton Zaides again](/reading/2026-07/2026-07-07t170607-the-software-engineering-war) frames the current moment as a split between "builders" who prioritize shipping fast with AI and "keepers" who insist on code quality, noting that where individuals land depends as much on who is in the room as on their actual beliefs. [DHg](/reading/2026-05/2026-05-08t112608-your-onboarding-is-a-hazing-ritual-and-you-call-it-agile) argues that poor onboarding practices disguised as agile process systematically set new hires up to fail. [Tuhin Nair](/reading/2026-05/2026-05-13t060018-why-senior-developers-fail-to-communicate-their-expertise) identifies a communication gap between senior engineers, who think in terms of complexity management, and the rest of the business, which thinks in terms of uncertainty reduction. [cekrem](/reading/2026-05/2026-05-19t110710-the-tacit-dimension-why-your-best-engineers-cant-tell-you) draws on Polanyi's philosophy of tacit knowledge to argue that the most valuable engineering expertise, including pattern recognition and design intuition, is structurally inaccessible to AI and can only be transmitted through apprenticeship.

Tooling and process occupy a wide span. [Sam Alba](/reading/2026-04/2026-04-30t195531-what-ci-actually-looks-like-at-a-100-person-team) describes an AI agent handling CI triage at PostHog's scale — 575K weekly jobs, 33M test executions — tracing flaky tests to root causes and opening fix PRs automatically. [Paolo Galeone](/reading/2026-08/2026-08-05t072544-use-your-brain-engineering-standards-in-the-age-of-llms) calls for strong CI/CD and code ownership to use AI as an amplifier rather than a crutch. [Pete Millspaugh](/reading/2026-05/2026-05-19t193626-slow-mode) proposes a "Slow Mode" agent that keeps the human involved at every step, trading short-term productivity for genuine learning and long-term code ownership. [Fagner Brack](/reading/2026-04/2026-04-30t155134-learn-algorithms-for-interviews-forget-them-for-work) argues that algorithm interviews test a narrow trainable skill that weakly correlates with production performance, while real engineering requires reading tradeoffs and shipping incrementally. [Anton Zaides](/reading/2026-08/2026-08-31t131721-the-i-dont-know-claude-wrote-this-pandemic) identifies cognitive ownership, the line between delegating to AI and blindly accepting its output, as the central professional question of the current moment.

The discipline's accumulated knowledge also continues to compound in concrete ways independent of AI. [Ivan Velichko](/reading/2026-05/2026-05-04t231858-how-container-filesystem-works-building-a-docker-like) builds a Docker-like container from scratch using only Linux primitives. [Robert Nystrom's Crafting Interpreters](/reading/2026-04/2026-04-30t231027-munificentcraftinginterpreters) remains a reference for understanding interpreter implementation end-to-end. [Yaron Minsky at Jane Street](/reading/2026-06/2026-06-15t021106-formal-methods-and-the-future-of-programming) argues that agentic coding has made formal methods newly cost-effective by lowering the cost of writing proofs while raising demand for verification that goes beyond what tests alone provide. Across all of this, the recurring question is not whether AI changes the practice of software engineering but which parts of the craft, judgment, ownership, communication, and design sensibility, remain distinctly human work.
